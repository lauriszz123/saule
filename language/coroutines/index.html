Coroutines

A coroutine is a function that can pause in the middle — yield a value — and later carry on from exactly that point, with every local and its whole call stack still in place. Where an ordinary function runs start to finish and returns once, a coroutine hands back a value every time it yields, as many times as it likes.

That makes coroutines the natural shape for anything that produces a sequence over time: a generator, a tokenizer that hands out one token at a time, a task in a game loop that runs a little each frame.

Nothing in the body runs until the first resume. Each resume runs it until the next yield, and the value given to yield is what that resume returns.

Two Handles: Coroutine<T> and Yielder<T>

Section titled “Two Handles: Coroutine<T> and Yielder<T>”

A coroutine has two sides, and each gets its own handle:

Handle Held by What it can do
Coroutine<T> Whoever created it resume(), status(), isDone(), error(), and for … in
Yielder<T> The body — its co parameter yield(value)

T is the type of the values that come out. The checker holds both sides to it: yielding anything else is a compile error, and resume() on a Coroutine<integer> answers an integer? — nil once the coroutine is done.

Splitting the handles is what makes yield typed. In Lua, coroutine.yield suspends whichever coroutine happens to be running, so nothing can say what type it should take. A Yielder<T> belongs to one coroutine, so it carries that coroutine’s T. It also keeps each side to the operations that make sense for it: the body cannot resume itself, and outside code cannot yield it.

Lifecycle and Status

Section titled “Lifecycle and Status”

status() says where a coroutine is:

Status Meaning
"suspended" Created but not started, or stopped at a yield
"running" Its code is running right now — only visible from inside it
"normal" It resumed another coroutine and is waiting for that one to yield
"dead" Its body finished, or failed

isDone() is true once it is dead. Resuming a dead coroutine is not an error — it simply answers nil again, which is what lets a loop drain a generator without checking first.

Coroutines can resume other coroutines, and do so freely: a pipeline of generators each pulling from the one before is just coroutines calling resume on each other.

When a Coroutine Fails

Section titled “When a Coroutine Fails”

A runtime error or an uncaught throw inside a coroutine does not end the program. The coroutine becomes dead, resume() answers nil, and error() says what went wrong — the thrown value for a throw, the message for anything else:

A throw the coroutine catches itself is ordinary control flow and does not fail it — a yield inside try resumes inside the same try.

for … in is the exception. A loop has no return value to report a failure in, and quietly ending would make a generator that crashed look like one that finished — so a coroutine that fails mid-loop raises out of the loop.

The Rules

Section titled “The Rules”

Coroutines run on one thread: resuming one transfers control to it, and nothing ever runs in parallel. Within that, three things are not allowed, and each is reported:

  • A coroutine cannot resume itself, nor one that is waiting on a coroutine it resumed. Both are already running.
  • A coroutine cannot yield from inside a callback that a built-in makes — a Table.sort comparator, an operator overload, a toString. The built-in’s own call sits between the callback and the coroutine and cannot be suspended. The coroutine fails, and error() explains. Resuming another coroutine from inside a callback is fine.
  • A yielder only yields its own coroutine, while that coroutine is running. One that escapes the body and is used later reports that it is not the one running.

Dynamic Coroutines

Section titled “Dynamic Coroutines”

The typed contract is fn(Yielder<T>) -> nil: values go out through yield, and resume takes no arguments. Lua’s coroutines go further — resume(x) becomes the result of the yield it resumes, the first resume passes arguments to the body, and the body’s return values reach the last resume.
