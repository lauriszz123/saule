### How it works

Your code runs **entirely in your browser**. Saule compiles to WebAssembly
from the same interpreter the `saule` CLI uses, so the type checker, the
diagnostics and the runtime all behave exactly as they do locally. Nothing is
sent to a server — there isn't one.

The module is about 330 KB gzipped and is fetched the first time you press
Run, so the first run takes a moment longer than the rest.

Programs execute in a Web Worker. That keeps the page responsive whatever your
code does, and it is what makes **Stop** possible: a WebAssembly module cannot
be interrupted from outside, so an infinite loop can only be escaped by
discarding the worker running it. Press **Stop** or hit <kbd>Esc</kbd>.
Anything still running after 10 seconds is stopped automatically.

**Copy link** encodes your program into the URL fragment, so you can share
exactly what you wrote — and because it is a fragment, it never leaves your
browser either.

### Notes on the sandbox

The playground runs in **single-file mode**, the same as `saule run file.sau`:
your program executes top-to-bottom and no `class Main` is required.

`import` is not available, because module resolution needs a filesystem the
browser does not have. Nor are the parts of `Os` and `Io` that touch real
files, processes or the network. Everything else — the full type system,
classes, interfaces, enums, pattern matching, closures, and the `String`,
`Math` and `Table` libraries — behaves exactly as it does locally.
