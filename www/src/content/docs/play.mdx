### How it works

Your code runs **entirely in your browser** — the same interpreter the `saule`
CLI uses, compiled to WebAssembly. Nothing is sent to a server, so the type
checker, the diagnostics and the output are the ones you would get locally.

The runtime is fetched the first time you press Run, so that run takes a
moment longer than the rest.

A program that will not finish on its own can be stopped with **Stop** or
<kbd>Esc</kbd>; anything still running after 10 seconds is stopped for you.

**Copy link** puts your program in the URL, so you can share exactly what you
wrote.

### Your own scripts

**New** starts a file of your own. It saves as you type, appears in the picker
under *My scripts*, and can be renamed or deleted from the toolbar. Examples
are never overwritten — **Save as my script** forks one into a file of yours.

Scripts live in this browser only: they survive a reload, but do not follow you
to another machine. Use **Copy link** to take one elsewhere.

### Notes on the sandbox

The playground runs in **single-file mode**, like `saule run file.sau`: your
program executes top-to-bottom, with no `class Main`.

`import` does not work here, nor do the parts of `Os` and `Io` that reach for
real files or processes — they fail with an error. Everything else — the full
type system, classes, interfaces, enums, pattern matching, closures, and the
`String`, `Math`, `Table` and `Iter` libraries — behaves exactly as it does
locally.
