Io / File

Io is the static entry point and holds the standard streams; a File is a reference-counted handle to an open file. Both the mode a file is opened in and the whence of a seek are real Saule enums — IoMode and IoSeek — so a typo is a compile error rather than a silent failure at run time.

The examples below write under Os.tmpname() so they run anywhere without leaving anything behind.

Streams

Section titled “Streams”

Io.stdin, Io.stdout and Io.stderr are File values that are already open. They need no Io.open and should not be closed.

IoMode variants

Section titled “IoMode variants”
Variant Mode What it does
Read r Read only; Io.open answers nil when the file does not exist
Write w Write only, truncating an existing file to empty
Append a Write only, every write going to the end
ReadWrite r+ Read and write, file must exist, not truncated
WriteRead w+ Read and write, truncating
AppendRead a+ Read anywhere, writes always at the end
ReadBinary rb As Read, in binary mode
WriteBinary wb As Write, in binary mode
AppendBinary ab As Append, in binary mode

The binary modes matter on Windows, where a text-mode handle translates \n to \r\n on the way out and back on the way in. For bytes that is corruption, so anything that is not text wants a binary mode.

IoSeek variants

Section titled “IoSeek variants”

Set counts from the start of the file, Cur from the current position and End from the end (where a negative offset moves backwards).

Static functions

Section titled “Static functions”
Io.open(path: string, mode: IoMode) -> File?

Opens path and answers a handle, or nil when it cannot — the file is missing, the directory is not writable, the path is a directory.

Nullable rather than throwing, because a file that is not there is an ordinary condition rather than an exceptional one.

Io.lines(path: string?) -> fn() -> string?

A step closure over the lines of path, written for for. With no argument it reads standard input instead.

The line separator is not included in what comes back, and the closure answers nil at end of file, which is what ends the loop.

Io.read(...string) -> string?

Reads from standard input in the given formats:

Format Reads
"l" One line, without its newline
"L" One line, keeping its newline
"a" Everything remaining, as one string
"n" One line, parsed as an integer; nil when it does not parse

A leading * is accepted on any of them ("*l"), for familiarity with Lua. There is no numeric byte-count format — for a fixed number of bytes, use f.readBytes(count).

nil at end of input, which is how a read loop knows to stop.

Io.write(...string) -> nil

Writes its arguments to standard output with nothing between them and no trailing newline. Io.stdout.write(...) is the same thing.

File methods

Section titled “File methods”

These are called with a dot, like every other method in Saule: handle.read("a"), never handle:read("a").

f.read(...string) -> string?

Reads from the handle in the same formats Io.read takes — "l", "L", "a" and "n". The result is a string, so this is for text: a file that is not valid UTF-8 needs readBytes, and so does a fixed number of bytes.

f.readBytes(count: integer?) -> bytes?

Reads raw bytes, assuming no encoding. With no argument it reads to end of file; with a count it reads up to that many and answers nil only at end of file — so a read loop terminates.

f.write(...string) -> nil

Appends text at the handle’s current position. A bytes passed here would be rendered as <bytes len=N> — use writeBytes.

f.writeBytes(data: bytes) -> nil

Appends the bytes themselves, with no encoding applied. Writing non-UTF-8 to stdout or stderr is an error rather than mojibake.

f.lines() -> fn() -> string?

A step closure over the handle’s remaining lines. The same as Io.lines, for a file you have already opened — which is what you want when the handle was opened in a particular mode, or when some of it has already been read.

f.seek(whence: IoSeek?, offset: integer?) -> integer?

Moves the read/write position and answers the new position, counted in bytes from the start. Defaults to (IoSeek.Cur, 0), which moves nothing and so answers where you are.

nil when the handle cannot seek — a pipe, or a closed file.

f.flush() -> nil

Forces buffered writes out to the file. Writes are buffered, so another reader — a different handle, another process — does not see them until the buffer is flushed or the handle is closed.

f.close() -> nil

Releases the handle, flushing whatever is buffered. Using a handle after closing it is an error, so close last.
