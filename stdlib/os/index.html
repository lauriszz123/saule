Os

Time, environment, filesystem and processes. This is the module that touches the world outside the program, so it is also where failure is most ordinary — see Failure conventions for which call reports it which way.

Constants

Section titled “Constants”
Name Type Value
Os.sep string The path separator: "/", or "\\" on Windows
Os.lineSep string The line ending: "\n", or "\r\n" on Windows

Time

Section titled “Time”
Os.time() -> integer

The current Unix epoch in seconds. Comparable across runs and across machines, which is what makes it the right thing to record.

Os.timeMillis() -> integer

The same instant in milliseconds — the resolution needed to time a request, a frame or a test.

Os.clock() -> float

Seconds from a monotonic clock: it never goes backwards, even if the system clock is adjusted, but its origin is arbitrary — only differences mean anything.

This is not Lua’s os.clock, which reports CPU time. Use Os.time for when something happened and Os.clock for how long it took.

Os.difftime(t2: integer, t1: integer) -> integer

t2 - t1. Present for familiarity with Lua; plain subtraction does the same thing here, because both arguments are already integers.

Os.date(format: string?, time: integer?) -> string

Formats a Unix epoch using strftime-style specifiers. format defaults to "%c" and time to now.

These are the specifiers that are implemented:

Specifier Gives Example
%Y Four-digit year 2021
%y Two-digit year 21
%m Month, zero-padded 01
%d Day of month, zero-padded 01
%j Day of year, zero-padded 001
%H %M %S Hours, minutes, seconds 00
%c Date and time 2021-01-01 00:00:00
%x Date only 2021-01-01
%X Time only 00:00:00

Anything else is passed through literally rather than reported — the name-based specifiers (%A, %B, %a, %b, %p) are not implemented, so Os.date("%B") answers the string "%B".

Os.parsedate(text: string, format: string?) -> integer?

The inverse of Os.date: reads text and answers the Unix epoch, or nil when it does not match. format defaults to "%Y-%m-%d".

Os.sleep(seconds: float) -> nil

Pauses the whole program. Fractions are allowed, so sub-second waits are ordinary.

Environment

Section titled “Environment”
Os.getenv(name: string) -> string?

The value of an environment variable, or nil when it is not set.

Os.setenv(name: string, value: string) -> nil

Sets a variable for this process and anything it spawns afterwards. It does not reach the shell that started the program.

Os.cwd() -> string

The absolute path of the current working directory.

Os.chdir(path: string) -> boolean

Changes the working directory, answering false when it cannot — the path does not exist, or is not a directory.

Filesystem

Section titled “Filesystem”
Os.exists(path: string) -> boolean

Whether anything exists at path — a file, a directory or a symlink.

Os.list(path: string) -> table<string>

The names of a directory’s children — names only, not full paths.

It is the one call here that fails hard. When the path cannot be read it raises a runtime error that ends the program; try / catch does not intercept it, because this is not a throw of a value. Its neighbours answer false or nil instead, so check with Os.exists or Os.fsInfo first when the path might not be there. That inconsistency is a known rough edge — see Failure conventions.

Os.mkdir(path: string, recursive: boolean?) -> boolean

Creates a directory, answering false when it cannot. With recursive set, it creates the missing parents too; without it, a missing parent is a failure.

Os.remove(path: string) -> boolean

Removes a file, or an empty directory. false when it cannot — the path is missing, or the directory still has something in it.

Os.rename(from: string, to: string) -> boolean

Moves or renames, answering false when it cannot. Within one filesystem this is atomic, which is what makes write-then-rename the safe way to replace a file.

Os.tmpname() -> string

A path under the system temp directory that nothing is using yet. It is a name, not a file: nothing is created until you create it.

Os.fsInfo(path: string?) -> FsInfo?

Metadata for one path, or nil when nothing is there. path defaults to the current directory.

The result is an FsInfo with these fields:

Field Type What it holds
path string The path this describes
kind FsKind File, Dir, Symlink or Other
size integer Size in bytes
modifiedAt integer Last-modified time, as a Unix epoch for Os.date
readOnly boolean Whether the permissions forbid writing

FsKind variants

Section titled “FsKind variants”

File ("file"), Dir ("dir"), Symlink ("symlink") and Other ("other"). Match on the variant rather than comparing .value when you want the compiler to check you have covered every case.

Process

Section titled “Process”
Os.pid() -> integer

This process’s own process id.

Os.args() -> table<string>

The command-line arguments passed to the script, without the interpreter or the script path.

Os.execute(cmd: string) -> integer

Runs cmd through the shell and answers its exit code. The child’s output goes to this process’s own stdout and stderr — nothing is captured.

-1 when the command could not be run at all.

Os.capture(cmd: string) -> (integer, string, string)

Runs cmd through the shell and captures it: the exit code, everything it wrote to stdout, and everything it wrote to stderr. Nothing reaches the terminal.

-1 with two empty strings when the command could not be run.

Os.spawn(program: string, args: table<string>?, cwd: string?, env: table<string, string>?) -> Process?

Starts program and answers a handle while it runs, so the program can write to it, read what came back, and carry on in between. nil when it cannot be started.

There is no shell: args is passed as a vector, so nothing re-parses quoting and a path with a space in it stays one argument. cwd sets the child’s working directory, and env adds to the environment it inherits rather than replacing it.

See Process handles for what the handle can do.

Os.exit(code: integer?) -> nil

Ends the process immediately with code, which defaults to 0. Nothing after it runs.

Os.platform() -> OsPlatform

Which operating system this is, as an enum: Linux, Macos, Windows or Other, whose .value is "linux", "macos", "windows" or "other".

Process handles

Section titled “Process handles”

Os.execute and Os.capture both block until the child is finished, so neither can be used to talk to one. Os.spawn is for a child with a conversation in it — a language server, a formatter fed on stdin, an editor embedded in a window: it returns while the child runs, and the program writes, reads what came back, and carries on in between.

Two properties shape everything below. Reads never block: each captured stream is drained on a thread of its own into a buffer, and read takes whatever has arrived so far. And reads are bytes, not string: a child’s output is not promised to be text, and a string is always valid UTF-8 — use Bytes.toString where you expect text, which returns string? precisely because that is where it can fail.

p.read(max: integer?) -> bytes

Whatever has arrived on stdout, up to max bytes (64 KiB by default). Never blocks: an empty buffer means “nothing yet”, which is not the same as “nothing more” — see p.atEof().

p.readErr(max: integer?) -> bytes

The same, for stderr. The two streams are separate, so output written to one never appears in the other.

p.write(data: bytes) -> integer

Writes to the child’s stdin and answers how many bytes went in. An error once stdin has been closed.

p.closeStdin() -> nil

Drops the child’s stdin so it sees end of input. Idempotent — closing twice has expressed one intention.

Anything that reads until EOF needs this, or both ends wait forever.

p.poll() -> integer?

The exit code if the child has finished, nil while it is still running. Remembered, so asking twice is fine.

p.wait() -> integer

Blocks until the child exits and its output has arrived, then answers its exit code. Closes stdin first — a child waiting for input and a parent waiting for the child is a deadlock, and this is the end that can tell.

Both halves matter: the exit status alone does not mean the output has been collected, so wait then read sees all of it rather than however much happened to arrive first.

p.kill() -> boolean

Ends the child. true when the signal was delivered, false when it had already exited — which is not an error.

p.running() -> boolean

Whether the child is still going. Asks the operating system rather than trusting a flag, so it is accurate without a prior poll.

p.pid() -> integer

The child’s process id.

p.available() -> integer

How many bytes are waiting on stdout, without taking them — how far behind a reader is.

Each stream buffers at most 8 MiB of unread output. At the limit the reader stops taking from the pipe, so the operating system’s own buffer fills and the child blocks on its next write: nothing is ever dropped, which for a binary protocol would be unrecoverable.

p.atEof() -> boolean

Whether stdout has ended and been drained. Both halves matter: a child can exit with output still sitting in the buffer, and reporting end of file then would lose it.

This is what makes a non-blocking read loop terminate correctly.

The child outlives the handle. Dropping the last reference does not kill it — call kill or wait.

Failure conventions

Section titled “Failure conventions”

The filesystem calls disagree about how they report trouble, and it is worth knowing which is which before you write the error handling:

  • Os.remove / Os.rename / Os.chdir / Os.mkdir return boolean.
  • Os.fsInfo and Os.getenv return T?.
  • Os.list throws.

None of the first two carry the operating system’s reason, so a failed call can’t tell “not found” from “permission denied”. That is a known rough edge, not a design.
