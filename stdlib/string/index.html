String

UTF-8 aware text utilities. Every index is 1-based and counted in characters, not bytes, so String.sub can never cut a multi-byte character in half. A negative index counts from the end, where -1 is the last character.

Most functions here operate on literal text: the . in String.replace(s, ".", "-") is a full stop, not “any character”. The three in Patterns — String.match, String.gmatch and String.gsub — read their pattern argument as a Lua-style pattern instead, where . is any character. Which language an argument is written in is decided by the function you call, never by a flag.

Characters and codepoints

Section titled “Characters and codepoints”
String.byte(s: string, i: integer?) -> integer?

The Unicode codepoint of the i-th character, or nil when i is outside the string. i defaults to 1, so a bare String.byte(s) reads the first character.

Nullable on purpose: a scan can walk off the end and stop, rather than needing a length check in front of every read.

String.char(...integer) -> string

Builds a string from codepoints. The inverse of String.byte.

Note what this is not: String.char(0x80) is the two-byte UTF-8 encoding of U+0080, because the result is text. For the single byte 0x80, reach for Bytes.of.

String.iter(s: string) -> fn() -> (string?, integer?)

A step closure over the characters of s, yielding each character and its 1-based index. Written for for, which stops when the closure answers nil.

Length and slicing

Section titled “Length and slicing”
String.len(s: string) -> integer

The number of characters, which is not the number of bytes. #s is not defined for a string — use this, and use #Bytes.fromString(s) when the byte count is what you want.

String.sub(s: string, from: integer, to: integer?) -> string

The substring from from to to, both inclusive and 1-based. to defaults to the end of the string. Either index may be negative to count from the end, and both clamp, so an out-of-range slice is empty rather than an error.

String.rep(s: string, n: integer) -> string

s repeated n times, with nothing between the copies. n of zero or less gives the empty string.

Case

Section titled “Case”
String.lower(s: string) -> string

Lowercases s. Unicode-aware, not ASCII-only: Š folds to š and Ė to ė, so this is correct for text in any language the string can hold.

String.upper(s: string) -> string

Uppercases s, Unicode-aware in the same way as String.lower.

Searching

Section titled “Searching”
String.find(s: string, needle: string, from: integer?) -> (integer?, integer?)

The 1-based start and end indices of the first occurrence of needle, or nil, nil when there is none. from says where to start looking and defaults to 1.

Two values, so you can slice around the match without measuring it. For just the start index, String.indexOf answers the same question with one value. needle is literal text; for the pattern form see String.match and Patterns.

String.indexOf(s: string, needle: string, from: integer?) -> integer?

The 1-based character index where needle first appears, or nil when it does not. from says where to start and defaults to 1.

String.find answers the same question and also gives the end index.

String.contains(s: string, needle: string) -> boolean

Whether needle appears anywhere in s. An empty needle is always present.

String.starts(s: string, prefix: string) -> boolean

Whether s begins with prefix. An empty prefix is always present.

String.ends(s: string, suffix: string) -> boolean

Whether s ends with suffix. An empty suffix is always present.

Splitting

Section titled “Splitting”
String.split(s: string, sep: string) -> table<string>

Splits s on every occurrence of sep. The result always holds one more piece than there were separators, so splitting the empty string gives one empty piece rather than none. An empty sep splits into single characters.

Joining

Section titled “Joining”
String.join<V>(sep: string, parts: table<V>) -> string

Joins parts with sep between them, rendering each element the way tostring would. The same operation as Table.concat, with the arguments the other way round so the call reads as a sentence.

Trimming

Section titled “Trimming”
String.trim(s: string) -> string

Removes whitespace from both ends. Unicode whitespace, not only the ASCII space — a non-breaking space goes too.

String.trimStart(s: string) -> string

Removes whitespace from the start only.

String.trimEnd(s: string) -> string

Removes whitespace from the end only.

Replacing

Section titled “Replacing”
String.replace(s: string, from: string, to: string, limit: integer?) -> string

Replaces every occurrence of from with to, or only the first limit of them when limit is given. Literal text, not a pattern. An empty from matches nothing and returns s unchanged, so this can never loop forever.

For the pattern form — where . is any character and (…) captures — see String.gsub. The two are separate functions rather than one with a flag, so that neither has an argument whose language you have to remember.

Padding

Section titled “Padding”
String.padStart(s: string, width: integer, fill: string?) -> string

Pads s on the left until it is width characters long. fill defaults to a single space and repeats if it is longer than one character. Never truncates: a string already at or past width comes back unchanged.

String.padEnd(s: string, width: integer, fill: string?) -> string

The same, padding on the right.

Formatting

Section titled “Formatting”
String.format(fmt: string, ...any) -> string

C-style formatting. The specifiers are %d and %i (integer), %f and %g (float), %s (any value, rendered as tostring would), %x and %X (hexadecimal), %o (octal), %c (a character from a codepoint) and %% for a literal percent sign.

Width, precision and flags work as they do in C: %-5s left-aligns in five columns, %05.1f pads with zeros to five columns with one decimal place.

Patterns

Section titled “Patterns”

String.find, String.replace and String.split all take literal text: String.replace(s, ".", "-") replaces full stops. The three functions in this group read their second argument as a pattern instead, where . means “any character”, %d means “a digit” and (…) captures part of the match.

These are Lua’s patterns, not regular expressions. There is no alternation (a|b) and no counted repetition (a{2,5}); what you get instead is a small language that fits in the table below, needs no separate engine, and is already familiar to anyone arriving from Lua.

Pattern syntax

Section titled “Pattern syntax”

A character class matches one character:

Class Matches
. any character
%a a letter
%d a digit, ASCII 0–9 only
%l a lowercase letter
%u an uppercase letter
%s whitespace
%w a letter or a digit
%x a hexadecimal digit
%p punctuation
%c a control character
%g any printable character except a space
%A, %D, %S, … the complement — any uppercase class letter negates it
[set] any character in the set: [aeiou], a range [a-z], or a class [%a_]
[^set] any character not in the set
%x where x is not a class letter the literal x — this is how you match %., %%, %(

A quantifier follows a class and repeats it:

Quantifier Meaning
* 0 or more, as many as possible
+ 1 or more, as many as possible
- 0 or more, as few as possible
? 0 or 1

And the rest of the language:

Item Meaning
^ anchor at the start of the subject — only meaningful as the first character
$ anchor at the end — only meaningful as the last character
(…) a capture: the text it matched is reported separately
%1–%9 match the same text capture 1–9 matched
%bxy a balanced pair: from x to its matching y, counting nesting — %b()
%f[set] a frontier: the empty position where the previous character is not in set and the next one is

Two differences from Lua, on purpose

Section titled “Two differences from Lua, on purpose”

Patterns run over characters, not bytes. A Saule string is always valid UTF-8 and is measured in codepoints, so . matches one character however many bytes it encodes to, and every index these functions report is a character index. In Lua, ("saulė"):gsub(".", "-") gives six dashes and can cut ė in half; here it gives five.

%a is Unicode-aware and %d is not. %a, %l, %u, %s and %w use the Unicode properties, so %a+ matches saulė and ąčę. %d is deliberately ASCII 0–9 only: a %d+ is almost always about to be read as a number, and the other digit systems a Unicode %d would match are not numbers any conversion would accept.

Not supported: a position capture, Lua’s (), which yields an integer index. Captures here are a table<string> and there is no honest integer to put in one — returning the digits as text would be a trap for whoever indexed with them. String.find already answers that question.

String.match(s: string, pat: string, from: integer?) -> table<string>?

The first match of pat in s, or nil when there is none. from says where to start looking and defaults to 1; a negative value counts back from the end.

On a match you get the captures, one element each, in the order they were opened. When the pattern declares no captures you get a one-element table holding the whole match — a pattern without parentheses captures itself, which is Lua’s rule, and it means m[1] is always “the interesting part”.

A table rather than two values, because of how this gets called: a single binding against a multi-return takes the whole tuple, so local m = String.match(s, p) would hand back a (string?, table<string>?) and every caller would have to destructure to reach anything.

String.gmatch(s: string, pat: string) -> fn() -> (string?, table<string>?)

A step closure over every match, for for … in. Each call reports the whole match and its captures; the loop ends when there are no more.

Two values here rather than one, because a for is flexible about how many it binds — unlike a local. So one loop variable costs nothing and gets the common case right, and a second is there when you want the captures:

A zero-width match advances by one character rather than matching forever, so String.gmatch(s, "%a*") terminates.

An anchored pattern is an error here, not an empty loop. ^ can match in one place only, so iterating it is a mistake somewhere — and both of the things an implementation could quietly do instead are worse. Lua reads the ^ as a literal character, so its gmatch(s, "^a") silently yields nothing; yielding exactly one match would silently turn the loop into an if. Use String.match for a single anchored match.

String.gsub(s: string, pat: string, repl: string, limit: integer?) -> (string, integer)

Every match of pat in s replaced by repl, and how many replacements were made. limit caps the count; without it every match is replaced.

repl is a template, not literal text:

In repl Inserts
%1–%9 capture 1–9
%0 the whole match
%% a literal %

Any other %x is an error rather than a silent literal, because at that point it is far more likely to be a typo than an intent.
