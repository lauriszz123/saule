Iter

Combinators over sequences. Where Table mutates a table or answers a question about one, Iter derives a new sequence and never writes to its argument.

Every combinator is eager: table in, table out. That is what keeps them typed. Iter.map<V, U>(t: table<V>, f: fn(V) -> U) binds V from the receiver, so a lambda written without annotations still gets a real parameter type, and the result is a real table<U> rather than an opaque iterator.

A step closure or an Iterable reaches these through Iter.collect, which drains it into a table first. That call is not overhead the design added: an eager map has to drain the source before it can run, so collect only makes visible a cost that was always there.

Collecting

Section titled “Collecting”
Iter.collect<V>(step: fn() -> V?) -> table<V>

Drains a step closure until it answers nil, collecting what it produced. This is the bridge from anything iterable — a String.iter, a File.lines, a class implementing Iterable — into the rest of this module.

A closure that never answers nil never terminates, exactly as a hand-written for loop over it would not.

Note that a closure yielding two values — String.iter, or an Iterable2 — collects into a table of pairs, not a table of its first value. Those are for for k, v in ... do rather than for this.

Transforming

Section titled “Transforming”
Iter.map<V, U>(t: table<V>, f: fn(V) -> U) -> table<U>

Applies f to every element, giving a new table of the results. The result type follows f’s return type, so mapping to a different type is ordinary.

Iter.filter<V>(t: table<V>, pred: fn(V) -> boolean) -> table<V>

Keeps the elements pred accepts, in their original order.

Iter.reduce<V, A>(t: table<V>, init: A, f: fn(A, V) -> A) -> A

Folds left from init, threading an accumulator through every element. The accumulator may be any type, not only the element type.

Iter.forEach<V>(t: table<V>, f: fn(V) -> nil) -> nil

Runs f for its effect on every element and answers nothing. Use it when the point is the side effect; use map when the point is the result.

Search

Section titled “Search”
Iter.find<V>(t: table<V>, pred: fn(V) -> boolean) -> V?

The first element pred accepts, or nil when none does.

Iter.findIndex<V>(t: table<V>, pred: fn(V) -> boolean) -> integer?

The 1-based position of the first element pred accepts, or nil.

Named apart from Table.indexOf, which searches for a value rather than with a predicate.

Iter.any<V>(t: table<V>, pred: fn(V) -> boolean) -> boolean

Whether any element matches. false for an empty table.

Iter.all<V>(t: table<V>, pred: fn(V) -> boolean) -> boolean

Whether every element matches. true for an empty table — there is no element that fails.

Iter.count<V>(t: table<V>, pred: fn(V) -> boolean) -> integer

How many elements match.

Slicing

Section titled “Slicing”
Iter.take<V>(t: table<V>, n: integer) -> table<V>

The first n elements, or all of them when there are fewer. Never an error.

Iter.skip<V>(t: table<V>, n: integer) -> table<V>

Everything after the first n elements. Empty when n is at or past the length.

Iter.first<V>(t: table<V>) -> V?

The first element, or nil when the table is empty.

Iter.last<V>(t: table<V>) -> V?

The last element, or nil when the table is empty.

Iter.chunk<V>(t: table<V>, size: integer) -> table<table<V>>

Fixed-size groups, in order. The last group is short when the length does not divide evenly.

Shaping

Section titled “Shaping”
Iter.zipWith<V, U, A>(a: table<V>, b: table<U>, f: fn(V, U) -> A) -> table<A>

Pairs the two tables up and combines each pair with f, stopping at the shorter one.

There is no plain zip, because a pair has no representation here: a two-element table holding an integer and a V types as table<any>, which loses both. Combining at the point the two elements meet keeps the types.

Iter.flatten<V>(t: table<table<V>>) -> table<V>

Concatenates the inner tables into one. One level only — nest the call to go deeper.

Iter.reverse<V>(t: table<V>) -> table<V>

A new table in reverse order. Table.reverse reverses in place instead.

Iter.unique<V>(t: table<V>) -> table<V>

Drops later duplicates, keeping the first occurrence and the original order. Compares with ==, so a class implementing OpEq is deduplicated by its own rule.

Iter.sortBy<V, K>(t: table<V>, key: fn(V) -> K) -> table<V>

A new table sorted ascending by the extracted key, using < — so a class implementing OpCompare sorts by its own rule. Stable: elements with equal keys keep their original order.

For a bespoke ordering, Table.sort takes a comparator directly.

Iter.groupBy<V, K>(t: table<V>, key: fn(V) -> K) -> table<K, table<V>>

Buckets the elements by key. The key must be a string, integer or boolean — the types a table can be keyed by.

There is no Iter.zip or Iter.enumerate

Section titled “There is no Iter.zip or Iter.enumerate”

Both would have to return pairs, and a pair has no representation here — zipWith combines at the point the two elements meet instead, and a for i, v in t do loop already gives indices alongside values.
